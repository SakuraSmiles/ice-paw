# 发版前手测清单

这 5 个功能代码写好了、自动测试也过了，但**还没在真 app 里点过**。发版前挨个跑一遍：勾掉「通过」就 OK，出现「失败」就别发版，回来修。

---

## 1. 中文不乱码
- **防的 bug**：agent 用 shell / git 工具时，中文输出变成乱码或闪退。
- **怎么测**：让 agent 用 shell 工具跑 `echo 你好世界`；再在一个有中文文件名的文件夹里跑一次 `git status`。
- ✅ 通过：中文正常显示。
- ❌ 失败：乱码 / 闪退。

## 2. 空文件不卡死
- **防的 bug**：拖一个 0 字节的空文件进来，整条消息就发不出去了。
- **怎么测**：新建一个空的 txt 或空 pdf（0 字节），拖进对话框发送。
- ✅ 通过：提示「文件是空的 / 读不了」，但消息照常发出、agent 正常回复。
- ❌ 失败：消息发不出去 / 卡死。

## 3. 发图给「不能看图」的模型
- **防的 bug**：agent 一边把图描述出来了，一边却说「我没看到、请重传」——自相矛盾。
- **怎么测**：用一个**普通文本模型**（不能看图的），发张图问「图里有什么」。
- ✅ 通过：agent 要么老实说「我看不了图」，要么自动把图转成文字回答。
- ❌ 失败：报 400 错 / 自相矛盾（描述了图却说没看到）。

## 4. 图纸 / 扫描件 PDF 能读
- **防的 bug**：图形为主的 PDF（户型图、工程图、图表、扫描件）agent 只读出零星文字标签、看不到图。
- **怎么测**：传一份**图纸或扫描件 PDF**（重点测"图纸"类——有文字标签但内容是图形，最容易漏），用任意 agent（视觉或非视觉都行，非视觉会自动代读），问「里面的布局 / 图形是什么」。
- ✅ 通过：agent 调读图工具、能说出图形 / 布局 / 内容。
- ❌ 失败：只报文字标签 / 报 dll 错 / 闪退 / 让你重传。

## 5. 知识库自动收录 + 长回答不断
- **5a 自动收录**　**防的 bug**：往知识库文件夹加新文件，要手动刷新才搜得到。
　　**怎么测**：给 agent 配好知识库文件夹，往里扔个新文件，过一会问 agent 这文件里的内容。
　　✅ 能搜到新文件　❌ 搜不到（得手动刷新才行）
- **5b 长回答不断**　**防的 bug**：回答太长会被硬截断在半句话。
　　**怎么测**：让 agent「写一篇 2000 字的文章」。
　　✅ 在同一个气泡里一直写到完　❌ 写到一半断掉 / 要手动点「继续」

## 6. 会话轨迹导出（调试出口）
- **防的 bug**：事件日志（session_events 影子写入）漏记了模型可见的事实。
- **怎么测**：发一条**带工具调用**的消息（如「读一下某个文件」）；等回答完，右键 →「检查」打开 DevTools，在控制台跑（`__TAURI_INTERNALS__` 始终注入，无需 withGlobalTauri）：
  ```js
  const inv = window.__TAURI_INTERNALS__.invoke;
  const convs = await inv('list_all_conversations');   // convs[0] = 最近活跃会话
  console.log(await inv('export_session_trajectory', { conversationId: convs[0].id }));
  ```
  拿到 JSONL 路径后打开。
- ✅ 通过：文件里能看到完整序列：`turn_context → user_message → assistant_message → tool_execution → tool_result_message → assistant_message → turn_ended`，seq 连续无空洞；`turn_ended` 里有终止原因和轮数。
- ❌ 失败：序列缺环（如只有 user_message 没有 turn_ended）/ seq 断号 / 文件没生成。
- 附带：给非视觉 agent 发一张图再导出一次，应看到 `modal_adapted` 事件且含代读文字。

## 7. 上下文开销可观测化（0.7 批③ · 判据留档）
> 2026-09-09 拍板：手测整体通过、生产使用驱动——本节**不是待办清单**，是日常使用中出疑点时的回查判据（出问题用户会报、报了即修）。

- **正常态长什么样**：
  - **轨迹页「上下文组成」区**：多轮工具会话回答完后，轨迹页点该轮 turn 头——概要页在「终止与用量」后有「上下文组成」区：段条形列表（人设/工具定义/历史消息等中文标签）+ 合计行（估算 vs 实际首轮输入 + 偏差%）+ 逐轮命中行（输入/命中/百分比，全 miss 轮带「全未命中」徽）+ 灰字披露脚注。
  - **预算 pill 的 miss chip**：输入框底部预算 pill 常态有「缓存命中 X%」；本轮全 miss（输入 ≥ 1024 且命中 0）的回合会出现灰字 chip（如「疑缓存过期」「工具列表变化」），hover 出全因机理与「本地推断，非 provider 报告」披露。首个请求不出现 chip（首次无缓存是正常态）。
  - **归因对得上变更**：改 agent 人设/工具集后下一条消息若全 miss，chip 应指「系统提示变化」/「工具列表变化」；改 project.md 或换工作目录后应为「运行环境变化」；降级换档后的回合应为「模型换档」。
- **什么算异常（要报的）**：provider 回传了 usage 的回合 turn 头整区不渲染；chip 归因与实际变更明显对不上（什么都没改却恒报「工具列表变化」——可能是相关性裁剪抖动误报）；出现 chip 但该轮明明有命中；轨迹页/聊天页因新事件渲染报错。
- **已知诚实缺席（不是 bug）**：provider 间歇不回 usage 的回合无 context_breakdown 事件（区不渲染）；估算与实际有偏差是既有已知债（偏差行 + 脚注披露，不追平）。
