## Agent 创建与编辑

### Agent 创建表单字段

**REQ-AGENT-001 文本输入字段渲染与输入**
- a. 标识符：REQ-AGENT-001
- b. 需求描述：`AgentForm.vue`（2.7.2）渲染三个文本输入字段：名称（input，1~50 字符，必填）、描述（input，0~500 字符，选填）、系统提示（textarea，0~5000 字符，选填）。用户通过键盘输入文本内容。
- c. 异常行为：名称或描述超出字符上限时，在 500ms debounce 后截断并高亮提示；系统提示超出 5000 字符时同上。
- d. 合格性方法：TEST

- c. 异常行为：上传失败时展示默认头像并用 toast 提示"头像上传失败"。
- d. 合格性方法：DEMO

**REQ-AGENT-003 模型选择器字段渲染**

- b. 需求描述：`AgentForm.vue` 渲染 `Select`（1.14）单选组件作为模型选择器，必填。
- c. 异常行为：无独立异常（Provider 列表加载异常在 REQ-AGENT-029 处理）。
- d. 合格性方法：DEMO

**REQ-AGENT-004 工具列表多选字段渲染**
- a. 标识符：REQ-AGENT-004
- b. 需求描述：`AgentForm.vue` 渲染 `Select`（1.14）多选组件作为工具列表选择器，选填。
- c. 异常行为：无独立异常（工具列表加载异常在 REQ-AGENT-024 处理）。
- d. 合格性方法：DEMO

**REQ-AGENT-005 必填字段即时校验**

### Agent 创建提交与持久化

**REQ-AGENT-006 Agent 创建提交**
- a. 标识符：REQ-AGENT-006
- b. 需求描述：Agent 创建表单校验通过后，`agents.ts` store（2.14.1）将表单数据序列化为 `CreateAgentRequest`，通过 bridge `invoke` 调用 `agent_cmd.rs`（3.3）的 `create_agent` 命令。
- c. 异常行为：① bridge 超时（30s）时前端 Toast "创建超时，请重试"；② 反序列化失败时 `agent_cmd` 返回 `AppError::InvalidInput`，前端 Toast "数据格式异常，请重试"。
- d. 合格性方法：TEST

**REQ-AGENT-007 后端 Agent 创建写入数据库**
- a. 标识符：REQ-AGENT-007
- b. 需求描述：`agent_cmd.rs` 收到 `create_agent` 请求后，校验字段合法性，调用 `repo/agent.rs`（3.11.1）执行参数化 INSERT，将 Agent 数据写入数据库，返回 `agent_id`。
- c. 异常行为：名称重复（唯一约束冲突）时 `agent_cmd` 返回 `AppError::DuplicateName`，前端在名称字段下方展示红色提示"Agent 名称已存在"。
- d. 合格性方法：TEST

**REQ-AGENT-008 Agent 创建成功后前端列表刷新**
- a. 标识符：REQ-AGENT-008
- b. 需求描述：`agent_cmd` 返回 `agent_id` 后，`agents.ts` store 将该 ID 插入本地 Agent 列表并触发响应式刷新，`AgentManagerPage.vue`（2.2）列表即时展示新 Agent。
- c. 异常行为：无独立异常（上游异常已在 REQ-AGENT-006/007 处理）。
- d. 合格性方法：TEST + DEMO

## Agent 工具权限配置

**REQ-AGENT-024 工具列表加载与展示**
- a. 标识符：REQ-AGENT-024
- b. 需求描述：`AgentForm.vue` 的工具多选组件（`Select` 1.14）从 `tool_registry/mod.rs`（3.15.1）加载已注册工具列表，每个工具展示名称、功能描述和危险级别标签（safe/warning/dangerous）。
- c. 异常行为：工具列表加载失败时前端 Toast "工具列表加载失败"，工具选择区域不可用但不阻断表单提交。
- d. 合格性方法：TEST

**REQ-AGENT-025 工具权限勾选与提交**
- a. 标识符：REQ-AGENT-025
- b. 需求描述：用户在 `AgentForm.vue` 勾选要授权的工具后，`agents.ts` store 将已选工具名数组 `allowed_tools: string[]` 序列化到 Agent 数据中，随创建或编辑请求一并提交到 `agent_cmd`。
- c. 异常行为：勾选了已删除工具名（旧数据残留）时，`authority.rs`（3.15.2）在运行时拒绝该工具调用并记录 WARN 日志，不阻断其他已授权工具。
- d. 合格性方法：TEST

**REQ-AGENT-026 空工具列表运行时处理**
- a. 标识符：REQ-AGENT-026
- b. 需求描述：当 Agent 的 `allowed_tools` 为空列表时，`loop_engine` 构建 API 请求时不向 LLM 传递 `tools` 定义。
- c. 异常行为：若 LLM 仍返回工具调用，`tool_executor` 拒绝执行并返回 `tool_result` 含 "no tools available" 错误信息回传 LLM。
- d. 合格性方法：TEST

**REQ-AGENT-027 工具调用运行时权限校验**
- a. 标识符：REQ-AGENT-027
- b. 需求描述：运行时 `authority.rs`（3.15.2）在每次工具调用前校验 LLM 请求的工具名是否在 Agent `allowed_tools` 列表中，不在列表中则拒绝执行。
- c. 异常行为：拒绝执行后返回 `tool_result` 含错误信息回传 LLM，不中断对话循环。
- d. 合格性方法：TEST + INSP（authority.rs 审查）

**REQ-AGENT-028 危险工具前端二次确认**
- a. 标识符：REQ-AGENT-028
- b. 需求描述：`useToolAuth.ts`（2.16.6）在工具调用执行前检查工具危险级别，对 `dangerous` 级别工具弹出 `ToolAuthDialog.vue`（2.8.13）要求用户确认后方可执行。
- c. 异常行为：用户拒绝确认时，`useToolAuth` 取消该次工具调用，`tool_executor` 返回 `tool_result` 含 "User denied tool execution" 回传 LLM。
- d. 合格性方法：TEST

## Agent 模型配置

**REQ-AGENT-029 Provider 列表加载与展示**
- a. 标识符：REQ-AGENT-029
- b. 需求描述：`AgentForm.vue` 的模型选择器（`Select` 1.14）从 `provider/mod.rs`（3.14.1）获取已配置 Provider 列表，以两级结构展示：第一级为 Provider 名称，第二级为该 Provider 下可用模型列表。
- c. 异常行为：Provider 列表为空或加载失败时，模型选择器置灰并展示提示"暂无可用 Provider，请先配置"。
- d. 合格性方法：TEST + DEMO

**REQ-AGENT-030 模型选择与绑定**
- a. 标识符：REQ-AGENT-030
- b. 需求描述：用户在模型选择器中选择 Provider 下的具体模型后，`AgentForm.vue` 将选中的 `provider`（Provider ID）和 `model`（模型名）绑定到 Agent 表单数据中。
- c. 异常行为：未选择模型时前端校验阻止提交并提示"请选择模型"。
- d. 合格性方法：TEST + DEMO

**REQ-AGENT-031 模型不可用运行时降级**
- a. 标识符：REQ-AGENT-031
- b. 需求描述：对话启动时，`ProviderAdapter` 校验 Agent 配置的模型在 Provider API 中是否可用。若模型不可用（API 返回 `model_not_found`），`error_mapping.rs`（3.13.6）将错误映射为用户可读提示。
- c. 异常行为：模型不可用时 `error_mapping.rs` 返回结构化错误，前端 Toast "所选模型暂不可用，请在 Agent 设置中更换模型"，对话不可静默失败。
- d. 合格性方法：TEST

**REQ-AGENT-032 Provider 运行时路由**
- a. 标识符：REQ-AGENT-032
- b. 需求描述：对话循环启动时，`loop_engine` 根据 Agent `provider` 字段动态路由到对应 `ProviderAdapter` 实现（OpenAI 对应 3.14.2 / Anthropic 对应 3.14.5）。
- c. 异常行为：`provider` 字段引用已删除 Provider 时，`loop_engine` 回退到 `default_provider` 策略并记录 WARN 日志，对话不可静默失败。
- d. 合格性方法：TEST

**REQ-AGENT-033 auto Provider 自动选择**
- a. 标识符：REQ-AGENT-033
- b. 需求描述：当 Agent `provider` 字段值为 `auto` 时，`loop_engine` 调用 `default_provider` 策略自动选择第一个可用 Provider 并路由到对应 `ProviderAdapter`。
- c. 异常行为：所有 Provider 均不可用时，`default_provider` 返回 `AppError::NoProviderAvailable`，前端 Toast "无可用 AI 服务，请检查 Provider 配置"。
- d. 合格性方法：TEST
