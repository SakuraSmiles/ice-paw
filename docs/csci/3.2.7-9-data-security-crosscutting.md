# CSCI §3.2 v4 — 数据存储 + 安全加密 + 跨切面（深度拆分）

> 拆分标准：b 描述出现「或/或者」→ 拆；出现「以及/同时/并/且」→ 拆；多种输入/操作方式 → 每种独立；多个处理步骤 → 每步独立；「与」连接可独立验收行为 → 拆。

## 3.2.7 数据存储能力

> 提供后端 SQLite 数据模型管理、数据访问、前端状态持久化能力，保障本地数据完整性与一致性。

### 3.2.7.1 数据模型

**REQ-DATA-001 实体数据模型定义**
- a. 标识符：REQ-DATA-001
- b. 需求描述：`packages/app/src-tauri/src/db/models.rs` 须定义全部实体（agent/conversation/message/project/template/preferences）的 Diesel 模型。
- c. 异常行为：模型字段类型不匹配时编译期报错。
- d. 合格性方法：TEST

### 3.2.7.2 数据迁移

**REQ-DATA-002 数据库迁移版本排序与启动执行**
- a. 标识符：REQ-DATA-002
- b. 需求描述：`packages/app/src-tauri/src/db/migrations/` 下 SQL 迁移文件须按版本号排序，应用启动时由 `db/mod.rs` 自动执行。
- c. 异常行为：迁移失败时应用启动中止并输出错误日志。
- d. 合格性方法：TEST

**REQ-DATA-002A 数据库迁移幂等保证**
- a. 标识符：REQ-DATA-002A
- b. 需求描述：`packages/app/src-tauri/src/db/migrations/` 下 SQL 迁移文件须保证幂等，重复执行不产生副作用（使用 `IF NOT EXISTS`）。
- c. 异常行为：重复迁移使用 IF NOT EXISTS 不产生副作用。
- d. 合格性方法：TEST

> **拆分依据**：原 REQ-DATA-002 b 描述包含版本排序执行与幂等保证两个可独立验收的行为（信号 5「与」级并列），拆为 REQ-DATA-002（排序 + 执行）+ REQ-DATA-002A（幂等保证）。

### 3.2.7.3 数据访问层

**REQ-DATA-003 Repository 参数化查询**
- a. 标识符：REQ-DATA-003
- b. 需求描述：`packages/app/src-tauri/src/db/repo/` 下各 Repository 须使用 Diesel 参数化查询，禁止字符串拼接 SQL。
- c. 异常行为：查询无结果时返回空集合而非 null。
- d. 合格性方法：TEST

### 3.2.7.4 前端状态持久化

**REQ-DATA-004 Store 后端命令调用**
- a. 标识符：REQ-DATA-004
- b. 需求描述：`packages/app/src/stores/` 下各 Pinia Store 须通过 `bridge.ts` 调用后端命令，无离线缓存依赖。
- c. 异常行为：Store 调用后端失败时设置 error 状态字段，由 Toast 展示用户友好消息。
- d. 合格性方法：TEST

**REQ-DATA-004A 用户偏好 localStorage 持久化**
- a. 标识符：REQ-DATA-004A
- b. 需求描述：`packages/app/src/stores/settings.ts` 须将用户偏好持久化到 localStorage。
- c. 异常行为：localStorage 写入失败（如配额超限）时 console.warn 记录错误，不阻断应用运行，偏好仅在内存中保留当次会话有效。
- d. 合格性方法：TEST

> **拆分依据**：原 REQ-DATA-004 b 描述用分号连接两个独立行为——通用 Store 经 bridge 调用后端与 settings.ts 持久化到 localStorage，两者涉及不同模块、不同机制、可独立验收（信号 5），拆为 REQ-DATA-004 + REQ-DATA-004A。

## 3.2.8 安全与加密能力

### 3.2.8.1 密钥加密存储

**REQ-SEC-001 API Key XChaCha20-Poly1305 加密落库（通过 Stronghold）**
- a. 标识符：REQ-SEC-001
- b. 需求描述：后端 `crypto.rs` 须使用 XChaCha20-Poly1305（通过 Stronghold vault）对 LLM Provider API Key 加密后写入 SQLite。
- c. 异常行为：用户主密码未设置时返回 `AppError::Crypto("master key not initialized")`。
- d. 合格性方法：TEST

> **拆分依据**：原 v3 REQ-SEC-001 b 描述包含密钥派生（blake2b256 通过 Stronghold）与加密落库两个独立处理步骤（信号 4），拆为 REQ-SEC-001（加密落库）+ REQ-SEC-001A（密钥派生）。

**REQ-SEC-001A 主密钥 blake2b256 派生（通过 Stronghold）**
- a. 标识符：REQ-SEC-001A
- b. 需求描述：后端 `crypto.rs` 主密钥须采用 blake2b256 算法（通过 Stronghold 密钥派生）派生，输出 32 字节。
- c. 异常行为：用户主密码未设置时派生过程中止，返回 `AppError::Crypto("master key not initialized")`。
- d. 合格性方法：TEST

**REQ-SEC-002 API Key 输入框掩码渲染**
- a. 标识符：REQ-SEC-002
- b. 需求描述：`SettingsGeneral.vue` API Key 输入框须以 `type="password"` 渲染，设置 `autocomplete="off"`。
- c. 异常行为：浏览器强制填充时在 `onMounted` 中清空输入值，确保不残留自动填充内容。
- d. 合格性方法：TEST

> **拆分依据**：原 v3 REQ-SEC-002 b 描述覆盖 UI 渲染与明文传输两个独立处理步骤（信号 4），拆为 REQ-SEC-002（掩码渲染）+ REQ-SEC-002A（明文传输）。

**REQ-SEC-002A API Key 明文传输无暂存**
- a. 标识符：REQ-SEC-002A
- b. 需求描述：API Key 提交时明文经 `bridge.ts` → `provider/mod.rs` 传输，前端不暂存明文。
- c. 异常行为：传输中断时提示「网络异常，请重试」，不残留明文于内存变量。
- d. 合格性方法：TEST

### 3.2.8.2 输入校验

- c. 异常行为：检测到恶意标签时移除该标签保留剩余内容，console.warn 记录被过滤标签名。
- d. 合格性方法：TEST

> **拆分依据**：原 v3 REQ-SEC-003 b 描述出现「及」（信号 2），连接标签/协议移除与事件属性移除两个可独立验收的行为，拆为 REQ-SEC-003 + REQ-SEC-003A。

**REQ-SEC-003A 前端 HTML 事件属性 Sanitize**
- a. 标识符：REQ-SEC-003A
- b. 需求描述：`MarkdownContent.vue` 须在渲染前对 HTML 做 sanitize，移除 `on*` 事件属性。
- c. 异常行为：检测到 `on*` 事件属性时移除该属性保留剩余内容，console.warn 记录被过滤属性名。
- d. 合格性方法：TEST

**REQ-SEC-004 后端字符串参数长度校验**
- a. 标识符：REQ-SEC-004
- b. 需求描述：后端 `commands/*.rs` 各 command 入口须对字符串参数做长度校验（≤32KB）。
- c. 异常行为：校验失败返回 `AppError::Validation`，前端 Toast 显示字段级错误信息。
- d. 合格性方法：TEST

> **拆分依据**：原 v3 REQ-SEC-004 b 描述出现「及」（信号 2），连接长度校验与字符白名单校验两个可独立验收的行为，拆为 REQ-SEC-004 + REQ-SEC-004A。

**REQ-SEC-004A 后端字符串参数字符白名单校验**
- a. 标识符：REQ-SEC-004A
- b. 需求描述：后端 `commands/*.rs` 各 command 入口须对字符串参数做字符白名单校验。
- c. 异常行为：校验失败返回 `AppError::Validation`，前端 Toast 显示字段级错误信息。
- d. 合格性方法：TEST

### 3.2.8.3 错误信息安全

**REQ-SEC-005 AppError Display 隐藏内部实现**
- a. 标识符：REQ-SEC-005
- b. 需求描述：`error.rs` 的 `AppError` 须实现 `Display`，面向用户消息不含文件路径、SQL 语句、堆栈帧。
- c. 异常行为：序列化或未知错误类型时 `tracing::error!` 记录完整上下文到本地日志。
- d. 合格性方法：INSP

**REQ-SEC-006 Provider 错误固定文案映射**
- a. 标识符：REQ-SEC-006
- b. 需求描述：`harness/error_mapping.rs` 须将 Provider 超时、鉴权失败映射为固定用户友好文案。
- c. 异常行为：映射未命中时兜底显示「操作失败，请重试」。
- d. 合格性方法：INSP

**REQ-SEC-007 前端错误 message 字段隔离**
- a. 标识符：REQ-SEC-007
- b. 需求描述：`bridge.ts` 反序列化 `TauriError` 后仅将 `message` 字段传递给 `Toast.vue`。
- c. 异常行为：反序列化失败时兜底显示「操作失败，请重试」。
- d. 合格性方法：INSP

**REQ-SEC-007A 前端错误 backtrace 开发模式限定**
- a. 标识符：REQ-SEC-007A
- b. 需求描述：`bridge.ts` 中 `TauriError` 的 `backtrace` 字段仅在 `import.meta.env.DEV` 下输出到 console。
- c. 异常行为：生产模式下 backtrace 不写入任何可访问位置。
- d. 合格性方法：INSP

> **拆分依据**：原 REQ-SEC-007 b 描述用分号连接两个独立行为——message 字段传递给 Toast（面向用户）与 backtrace 仅 DEV 模式 console 输出（面向开发者），两者目标受众不同、传递路径不同、可独立验收（信号 5），拆为 REQ-SEC-007 + REQ-SEC-007A。

## 3.2.9 跨切面能力

### 3.2.9.1 前后端数据同步

**REQ-XC-001 乐观更新与回滚**
- a. 标识符：REQ-XC-001
- b. 需求描述：Pinia store 写操作须先乐观更新本地状态再调用 bridge；command 返回值与乐观值不一致时回滚本地状态。
- c. 异常行为：IPC 超时（>30s）时回滚乐观更新并标记 `syncError`，用户可手动重试。
- d. 合格性方法：DEMO

> **拆分依据**：原 v3 REQ-XC-001 b 描述出现「并」（信号 2），连接回滚（数据行为）与触发 Toast（UI 行为）两个可独立验收的行为，拆为 REQ-XC-001 + REQ-XC-001A。

**REQ-XC-001A 回滚时 Toast 用户通知**
- a. 标识符：REQ-XC-001A
- b. 需求描述：command 返回值与乐观值不一致而触发回滚时，须同步弹出 Toast 提示用户数据已恢复。
- c. 异常行为：IPC 超时场景下由 `syncError` 状态标记驱动重试入口，不额外弹出 Toast。
- d. 合格性方法：DEMO

**REQ-XC-002 流式消息追加节流**
- a. 标识符：REQ-XC-002
- b. 需求描述：`stream_consumer.rs` SSE token 经 bridge → `chat.ts` store 追加，追加间隔 ≤16ms。
- c. 异常行为：追加队列入积压时丢弃过期帧，保证最新 token 及时渲染。
- d. 合格性方法：DEMO

### 3.2.9.2 性能保障

**REQ-XC-003 消息列表虚拟滚动**
- a. 标识符：REQ-XC-003
- b. 需求描述：`MessageList.vue` 单会话 ≥500 条消息时须启用虚拟滚动，可见 DOM 节点 ≤30。
- c. 异常行为：虚拟滚动计算异常时降级为全量渲染并 console.warn，不阻塞主线程。
- d. 合格性方法：TEST

**REQ-XC-004 后端流式写入 Token 批次 Flush**
- a. 标识符：REQ-XC-004
- b. 需求描述：`repo/message.rs` 流式写入须按 ≥50 token 批次 flush 到 SQLite。
- c. 异常行为：批次未满时关闭流后须执行最终 flush，不丢数据。
- d. 合格性方法：TEST

> **拆分依据**：原 v3 REQ-XC-004 b 描述出现「或」（信号 1），连接 token 数量阈值与时间阈值两个独立批处理条件，拆为 REQ-XC-004 + REQ-XC-004A。

**REQ-XC-004A 后端流式写入时间批次 Flush**
- a. 标识符：REQ-XC-004A
- b. 需求描述：`repo/message.rs` 流式写入须按 ≥200ms 时间窗口批次 flush 到 SQLite。
- c. 异常行为：时间窗口未触发时关闭流后须执行最终 flush，不丢数据。
- d. 合格性方法：TEST

**REQ-XC-005 后台暂停 CSS 动画**
- a. 标识符：REQ-XC-005
- b. 需求描述：`ThinkingBlock.vue` 在 `document.hidden` 时须暂停 CSS 动画以释放 GPU。
- c. 异常行为：页面重新可见时自动恢复动画，无需手动刷新。
- d. 合格性方法：TEST

### 3.2.9.3 应用生命周期

**REQ-XC-006 后端冷启动有序初始化**
- a. 标识符：REQ-XC-006
- b. 需求描述：`main.rs` 冷启动须按「DB 连接池 → migration → crypto 初始化 → Provider 注册 → tool_registry 注册」顺序完成。
- c. 异常行为：任一步骤失败须终止启动并 `tracing::error!` 记录失败步骤；migration 失败时 panic 并提示用户检查数据库文件权限。
- d. 合格性方法：DEMO

**REQ-XC-007 首屏 TTI 保障**
- a. 标识符：REQ-XC-007
- b. 需求描述：前端首屏 TTI ≤3s（冷启动）。
- c. 异常行为：超出 3s 时仍须显示骨架屏，不得白屏。
- d. 合格性方法：DEMO

**REQ-XC-008 窗口关闭取消信号传播**
- a. 标识符：REQ-XC-008
- b. 需求描述：`infra/cancel.rs` 的 CancellationToken 须在窗口关闭时向 `loop_engine.rs` 及活跃 Provider stream 传播取消信号，stream 须在 500ms 内关闭连接并释放 buffer。
- c. 异常行为：取消传播超 500ms 未到达时记录 `tracing::warn!` 并强制 drop stream 句柄。
- d. 合格性方法：DEMO

> **拆分依据**：原 v3 REQ-XC-008 b 描述出现「或」（信号 1），连接窗口关闭与用户中止两个独立触发条件，拆为 REQ-XC-008 + REQ-XC-008A。

**REQ-XC-008A 用户中止取消信号传播**
- a. 标识符：REQ-XC-008A
- b. 需求描述：`infra/cancel.rs` 的 CancellationToken 须在用户中止操作时向 `loop_engine.rs` 及活跃 Provider stream 传播取消信号，stream 须在 500ms 内关闭连接并释放 buffer。

- d. 合格性方法：DEMO

### 3.2.9.4 可测试性

**REQ-XC-009 Repository 层测试隔离**

- d. 合格性方法：TEST

## 拆分摘要

| 原 REQ | 拆分信号 | 拆分后 | 说明 |
|--------|----------|--------|------|
| REQ-DATA-002 | 信号5（并列行为） | REQ-DATA-002 + REQ-DATA-002A | 版本排序执行 / 幂等保证 |
| REQ-DATA-004 | 信号5（分号隔开独立行为） | REQ-DATA-004 + REQ-DATA-004A | Store bridge 调用 / settings localStorage 持久化 |
| REQ-SEC-001 | 信号4（多步骤） | REQ-SEC-001 + REQ-SEC-001A | XChaCha20-Poly1305 加密落库（通过 Stronghold）/ blake2b256 密钥派生（通过 Stronghold） |
| REQ-SEC-002 | 信号4（多步骤） | REQ-SEC-002 + REQ-SEC-002A | 掩码渲染 / 明文传输无暂存 |
| REQ-SEC-003 | 信号2（「及」） | REQ-SEC-003 + REQ-SEC-003A | 标签与协议 sanitize / 事件属性 sanitize |
| REQ-SEC-004 | 信号2（「及」） | REQ-SEC-004 + REQ-SEC-004A | 长度校验 / 字符白名单校验 |
| REQ-SEC-007 | 信号5（分号隔开独立行为） | REQ-SEC-007 + REQ-SEC-007A | message→Toast 隔离 / backtrace DEV-only console |
| REQ-XC-001 | 信号2（「并」） | REQ-XC-001 + REQ-XC-001A | 乐观更新回滚 / 回滚 Toast 通知 |
| REQ-XC-004 | 信号1（「或」） | REQ-XC-004 + REQ-XC-004A | Token 批次 flush / 时间窗口批次 flush |
| REQ-XC-008 | 信号1（「或」） | REQ-XC-008 + REQ-XC-008A | 窗口关闭触发 / 用户中止触发 |

**统计**：
- §3.2.7 数据存储能力：5 条 REQ（原 4 条 → +1 拆分：DATA-002A、DATA-004A）
- §3.2.8 安全与加密能力：10 条 REQ（原 7 条 → +3 拆分：SEC-001A、SEC-002A、SEC-003A、SEC-004A、SEC-007A，净增 3 条）
- §3.2.9 跨切面能力：13 条 REQ（原 11 条 → +2 拆分：XC-001A、XC-004A、XC-008A，净增 2 条）
- **合计：28 条 REQ**（原 22 条 → +9 条拆分项 → 净增 6 条）
