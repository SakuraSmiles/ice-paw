# CSCI §3.2.6 v4 — UI 基础能力（深度拆分）

> 拆分标准：b 描述出现「或/或者」→ 拆；出现「以及/同时/并/且」→ 拆；多种输入/操作方式 → 每种独立；多个处理步骤 → 每步独立；「与」连接可独立验收行为 → 拆。
>
> 额外推论：不同组件（不同文件路径）→ 拆；同一组件内不同交互状态（禁用 / 加载 / 正常）→ 各自独立可验收 → 拆；同一组件内不同功能特性（搜索 / 分页 / 预览 / 校验）→ 拆。

---

## 3.2.6 UI 基础能力

> 提供设计系统级通用组件，为所有业务页面提供一致的交互、布局、反馈、展示、媒体、选择能力。组件位于 `packages/ui/src/components/` 下，无后端依赖。

---

### 3.2.6.1 通用交互组件

#### Button

**REQ-UI-001 Button 视觉变体与尺寸渲染**
- a. 标识符：REQ-UI-001
- b. 需求描述：`packages/ui/src/components/button/` 须支持 ≥3 种视觉变体（variant）和 ≥2 种尺寸（size），通过 props 配置渲染对应样式。
- c. 异常行为：传入非法 variant/size 值时回退到默认值并 `console.warn`。
- d. 合格性方法：TEST

**REQ-UI-001A Button 禁用态交互**
- a. 标识符：REQ-UI-001A
- b. 需求描述：Button 组件须支持 `disabled` 属性，设为 `true` 时按钮呈现禁用视觉样式，不触发 `click` 事件。
- c. 异常行为：`disabled` 与 `loading` 同时为 `true` 时，以 `loading` 态优先展示加载指示器，仍不触发 `click`。
- d. 合格性方法：TEST

**REQ-UI-001B Button 加载态展示**
- a. 标识符：REQ-UI-001B
- b. 需求描述：Button 组件须支持 `loading` 属性，设为 `true` 时按钮内展示加载指示器（spinner），期间不触发 `click` 事件。
- c. 异常行为：`loading` 结束后加载指示器消失，按钮恢复可交互态。
- d. 合格性方法：TEST

**REQ-UI-001C Button 无障碍 aria-label 支持**
- a. 标识符：REQ-UI-001C
- b. 需求描述：Button 组件须支持 `aria-label` 属性，屏幕阅读器可读取按钮用途说明。
- c. 异常行为：未传入 `aria-label` 时不影响按钮正常渲染与交互。
- d. 合格性方法：TEST

> **拆分依据**：原 REQ-UI-001 b 描述使用顿号并列变体、尺寸、禁用态、加载态、aria-label 五个独立可验收行为（渲染配置 / 交互状态 / 视觉状态 / 无障碍），各自验证方法与异常路径不同，拆为 4 条。variant 与 size 同属视觉渲染配置、验证方法一致，合并保留。

#### Input / Textarea

**REQ-UI-002 Input/Textarea 视觉变体与尺寸渲染**
- a. 标识符：REQ-UI-002
- b. 需求描述：`packages/ui/src/components/input/` 与 `packages/ui/src/components/textarea/` 须各支持 ≥3 种视觉变体（variant）和 ≥2 种尺寸（size），通过 props 配置渲染对应样式。
- c. 异常行为：传入非法 variant/size 值时回退到默认值并 `console.warn`。
- d. 合格性方法：TEST

**REQ-UI-002A Input/Textarea 禁用态交互**
- a. 标识符：REQ-UI-002A
- b. 需求描述：Input 与 Textarea 组件须支持 `disabled` 属性，设为 `true` 时输入框不可聚焦、不可编辑、不触发 `input`/`change` 事件。
- c. 异常行为：`disabled` 态下已有值仍正常展示，仅交互被抑制。
- d. 合格性方法：TEST

**REQ-UI-002B Input/Textarea 加载态展示**
- a. 标识符：REQ-UI-002B
- b. 需求描述：Input 与 Textarea 组件须支持 `loading` 属性，设为 `true` 时在输入框区域展示加载指示器。
- c. 异常行为：`loading` 态不影响输入框已有值的显示。
- d. 合格性方法：TEST

**REQ-UI-002C Input/Textarea 前缀后缀插槽**
- a. 标识符：REQ-UI-002C
- b. 需求描述：Input 与 Textarea 组件须提供 `prefix` 和 `suffix` 具名插槽，用于在输入框内部前后区域渲染自定义内容（如图标、单位标签）。
- c. 异常行为：未传入插槽内容时不渲染额外区域，输入框布局不受影响。
- d. 合格性方法：DEMO

**REQ-UI-002D Input/Textarea 清除按钮**
- a. 标识符：REQ-UI-002D
- b. 需求描述：Input 与 Textarea 组件须在输入框有值时展示清除按钮（×），点击后清空输入内容并触发 `input` 事件。
- c. 异常行为：输入框为空时不展示清除按钮；`disabled` 态下清除按钮不响应点击。
- d. 合格性方法：TEST

> **拆分依据**：原 REQ-UI-002 b 描述使用顿号 + 分号并列变体尺寸、禁用态、加载态、前缀后缀插槽、清除按钮五个独立可验收行为，各自验证场景不同（渲染配置 / 交互禁止 / 视觉指示 / 插槽渲染 / 用户操作），拆为 5 条。

### 3.2.6.2 布局组件

#### Flex

**REQ-UI-004 Flex 布局属性渲染**
- a. 标识符：REQ-UI-004
- b. 需求描述：`packages/ui/src/components/flex/` 须支持 `gap`、`align`、`direction` 三个布局属性，通过 props 控制子元素间距、交叉轴对齐方式和主轴排列方向。

**REQ-UI-004A Flex 响应式断点适配**
- a. 标识符：REQ-UI-004A
- b. 需求描述：Flex 组件须提供 ≥3 个响应式断点（mobile / tablet / desktop），在不同视口宽度下自动调整布局属性值。

- d. 合格性方法：DEMO

> **拆分依据**：原 REQ-UI-004 b 描述使用分号连接布局属性配置与响应式断点两个独立可验收行为（静态布局渲染 vs 视口自适应），验证方法不同（固定 props 验证 vs 改变视口宽度验证），拆为 2 条。

### 3.2.6.4 反馈组件

#### Modal

**REQ-UI-006 Modal ESC 键关闭**
- a. 标识符：REQ-UI-006
- b. 需求描述：`packages/ui/src/components/modal/` 须支持按 ESC 键关闭模态框，ESC 事件仅在 Modal 打开态下生效。
- c. 异常行为：Modal 配置 `closeOnEsc=false` 时 ESC 键不关闭。
- d. 合格性方法：TEST

**REQ-UI-006A Modal 背景滚动锁定**
- a. 标识符：REQ-UI-006A
- b. 需求描述：Modal 打开时须将 `document.body.style.overflow` 设为 `hidden`，禁止背景页面滚动。
- c. 异常行为：Modal 关闭后 `body overflow` 恢复为打开前的原始值；多个 Modal 嵌套关闭内层时外层仍保持锁定。
- d. 合格性方法：TEST

#### Toast

**REQ-UI-006B Toast 多类型渲染**
- a. 标识符：REQ-UI-006B
- b. 需求描述：`packages/ui/src/components/toast/` 须支持 5 种消息类型：`info`、`success`、`warning`、`error`、`loading`，每种类型对应独立图标与配色方案。
- c. 异常行为：传入未知类型时回退为 `info` 类型渲染。
- d. 合格性方法：TEST

**REQ-UI-006C Toast 自动消失**
- a. 标识符：REQ-UI-006C
- b. 需求描述：Toast 展示后须在 3 秒后自动从 DOM 中移除；`loading` 类型不自动消失，须由调用方手动关闭。
- c. 异常行为：Toast 队列超过 5 条时自动移除最早条目。
- d. 合格性方法：TEST

#### Popconfirm

**REQ-UI-006D Popconfirm 异步确认回调**
- a. 标识符：REQ-UI-006D
- b. 需求描述：`packages/ui/src/components/popconfirm/` 须支持异步确认回调，用户点击「确认」后执行传入的异步函数，确认按钮期间展示加载态。
- c. 异常行为：异步函数抛出异常时关闭加载态，Popconfirm 保持打开，不自动关闭；用户点击「取消」时直接关闭 Popconfirm，不执行异步函数。
- d. 合格性方法：TEST

> **拆分依据**：原 REQ-UI-006 b 描述覆盖 Modal、Toast、Popconfirm 三个不同组件（信号：不同组件、不同文件路径），且 Modal 内部 ESC 关闭与滚动锁定是两个独立机制（信号 4：多个处理步骤），Toast 类型渲染与自动消失是两个独立行为，共拆为 5 条。

### 3.2.6.6 媒体组件

#### AvatarUpload

> **拆分依据**：原 REQ-UI-008 b 描述覆盖 Avatar（`avatar/`）与 AvatarUpload（`avatar-upload/`）两个不同组件（信号：不同组件），且 Avatar 内部图片回退与在线状态展示是两个独立渲染行为，共拆为 3 条。
