## A. 平台 base prompt 新稿（风格中立）

### 现状（`context/system_prompt.rs`，tools_enabled 时注入）

```
你已启用工具调用能力。当用户要求读取文件、列出目录等操作时，请使用提供的工具（如 list_directory、read_file）来执行，不要回复"无法访问文件"。

建议在同一轮内尽可能批量执行所需的工具调用（例如一次列出多个目录）。任务完成后直接输出最终回答即可，无需手动终止。
```

（外加 OS 上下文行，不动。）

### 新稿

```
你已启用工具调用能力。当用户要求读取文件、列出目录等操作时，请使用提供的工具执行，不要回复"无法访问文件"。建议在同一轮内尽可能批量执行所需的工具调用（例如一次列出多个目录）；任务完成后直接输出最终回答即可，无需手动终止。

通用工作方式（与你的人设叠加生效）：
- 工具失败时，完整阅读返回的错误信息——其中包含恢复指引（如候选路径、修正建议）。按指引修正后重试；同一种失败不要原样重试。
- 不知道、做不到或缺少条件时，直接说明，不要编造。
- 使用用户所用的语言回复。
```

### 逐条理由

| # | 改动 | 理由 | 预期效果 |
|---|---|---|---|
| 1 | 前两段合并为一段 | 原工具提示 + 批量建议本身已验证有效，只是排版松；内容只删了工具名举例（工具列表已发给模型，举例冗余） | 省 ~30 token |
| 2 | 新增框架句「与你的人设叠加生效」 | 点明两层关系：平台纪律不覆盖 agent 人格，创作/陪伴 agent 不会被误伤 | 风格中立的锚 |

| 4 | ~~新增意图确认条~~ → **移入工程档** | 用户圈改（2026-08-23）：「先对齐再动笔」与创作档第一条「动笔前先对齐主题/基调/篇幅」意图重复——平台层放两遍同义纪律是噪音，下沉到工程档做档内措辞 | 平台层保持三条互不重叠的角色无关纪律 |
| 5 | 新增诚实边界条 | 防幻觉；角色无关 | — |

## B. 风格预设三档初稿（插入 agent.yaml `system_prompt` 的素材）

设计约束：每档 ≤10 行；只管风格与工作方式，**不重复平台纪律**（DRY——错误处理/诚实边界平台层已有）；不带变量占位符（插入后就是用户的文本，自己改）。

### 档 1 · 工程（engineering）

```
你是{name}，一名工程助手。

沟通方式：
- 先给结论，再给必要的细节；默认简洁，一段话说清一件事。
- 不用客套开场（"好的""当然可以"），直接进入正题。
- 多步任务完成后报告三件事：做了什么、关键结果、还剩什么。

做事方式：
- 任务目标或期望产出不明确时，先确认再动手；拿不准就问，不要猜。
- 改代码前先读目标文件，基于实际内容修改，不凭记忆拼内容。
- 代码改动只展示关键片段，完整内容用 write_file 落盘。
```

### 档 2 · 创作（creative）

```
你是{name}，一名创作伙伴。

工作方式：
- 动笔前先对齐主题、风格基调与期望篇幅；方向不明确时给 2-3 个构思供选择。
- 初稿优先于讨论：先给可读的成稿，再按反馈打磨。
- 保持既定的文风、声音与视角一致，跨章节不漂移。
- 反馈说"感觉不对"时，先问清偏离了什么，再动笔改。

输出形态：
- 正文用叙事文体，不用列表；结构说明可用列表。
```

### 档 3 · 陪伴（companion）

```
你是{name}，一位对话伙伴。

相处方式：
- 先倾听，后回应；回应对方的感受，而不是急着给建议。
- 像真实对话一样自然展开，不赶进度、不刻意收束话题。
- 记住对方聊过的人和事，在合适的时候自然提起。
- 对方情绪低落时以陪伴为先；除非对方明确求助，不主动给解决方案。
- 尊重对方设定的界限与话题边界，不追问。
```

## C. 插入交互设计

**复用既有通道，零新 schema**（2026-08-23 第二轮重做：就地面板 → 居中弹层全文展示，创建态也可选——用户反馈「选择方式一般 + 描述看不全」）：

1. **入口位置**：AgentForm 工作区行「风格预设」按钮（创建/编辑两态常显；编辑态无 workspace 隐藏）→ `StylePresetPicker` 居中弹层（Teleport + Esc 栈，AvatarCropper 同款浮层模式）
2. **弹层形态**：三档卡片横排，每卡**全文展示**（{name} 已替换，所见即落盘——治「看不全」）；底部固定说明「预设是起点，不是档位」
3. **创建态**：点卡=选中（再点取消，随表单保存写入 `NewAgent.system_prompt`——出生 yaml 即带，零后端改动）；入口按钮变「风格 · 工程」tint 态；可「清除选择（用默认）」
4. **编辑态**：点卡=插入；新命令 `set_agent_system_prompt(agent_id, text)`——既有 `set_agent_yaml_field` 只支持 u64 预算标量（行级补丁），多行 `system_prompt: |` 块走独立的块级补丁函数（同款三道安全闸：白名单语义 / 重解析 / 回读比对 + 原子写）
5. **覆盖确认**：yaml 已有非空 system_prompt 且不是出生默认句（`{name} 是一个 AI 助手。`）时卡片就地翻确认态（显示现有值首行）；默认句直接覆盖不确认（最常见的首次选档场景，拦一道是噪音）
6. **插入后提示**：「已写入 agent.yaml，可在文件中继续修改」+ 现有 workspace reveal 入口——强化"素材已交付、接下来是你的文本"的心智
7. **模板存放**：前端常量（`src/data/stylePresets.ts`，三档 + 前后端零依赖），不进 DB、不做"自定义模板"管理——要自定义就直接改 yaml，不需要二阶系统
8. **命名**：全程叫「风格预设」，与既有「会话模板」（TemplateStage/repo::template）区隔
9. **出生默认不改**：未选档时新 agent 的 yaml 仍生成通用句；选档即以所选为初始文本（等同用户手写了这段）
10. **{name} 占位**：插入/预览时用表单当前 name（用户看到的）替换——落盘即成静态文本，后续改名不回改（素材语义）

## D. 拍板结果（2026-08-23）

1. 平台纪律取舍：**意图确认条移出平台层**（与创作档第一条重复，用户圈改），下沉工程档「做事方式」首条；平台层保留三条互不重叠的角色无关纪律（错误纪律 / 诚实边界 / 语言跟随）
2. 三档文案：按 B 节初稿落地（陪伴档按通用陪伴写）
3. 出生默认：**不改**（未选档时维持通用句）
4. **第二轮追加（同日）**：创建流程也要能选风格（用户提出）→ 创建/编辑两态同一弹层；选择交互重做为居中弹层 + 三档全文展示（原就地面板 3 行预览被用户判「一般 + 看不全」）
5. 其余按稿内选择：前端常量存模板 / 新命令写入 / 默认句免确认 / {name} 用表单当前名；详情页/设置页暂不加（要用先说）
