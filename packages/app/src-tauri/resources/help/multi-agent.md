# 多 agent 协作（委派与跨会话通讯）

一个项目里往往有多个 agent 各有所长（写作、编码、查资料）。IcePaw 提供两条协作通道，加上**频道**（项目成员群聊，见「频道」篇），三者分工明确：

| 方式 | 节奏 | 单位 | 适用 |
|---|---|---|---|
| 委派（delegate） | 同步阻塞，父 agent 等结果 | 任务 | 「这段代码让编码专家写一下」 |
| 跨会话通讯（投递） | 异步，不等回复 | 对话 | 「把这个结论告诉那个会话的 agent」 |
| 频道（channel） | 串行圆桌，全员共享一条流 | 群聊 | 项目成员一起讨论（另见专篇） |

## 委派：同步派活给专家

在普通会话（1v1）里，agent 可以调用**委派**把一整块任务交给另一个 agent 完成：

- 你会看到一张**委派审批卡**（目标 agent + 任务全文），批准后子会话才开跑——委派是「别的 agent 将以它自己的模型和工具跑完整子任务」的高信任动作，决策权在你。
- 审批卡上可选**预授权**档（如「命令免问」）：子 agent 执行命令类工具时不再逐条弹窗。默认逐次审批。
- 子会话有独立的预算与事件轨迹；完成后结果回到**当前会话**继续（父 agent 拿到结果接着干），父会话里能看到委派卡与耗时，点击可进入子会话查看全程。
- 委派深度为 1：子 agent 不能再往下委派（防失控链）。
- 模型降级链：子 agent 自己配了链就用自链；没配则继承父 agent 的配置链。

> 委派只在 1v1 会话可用；频道里刻意禁用（频道历史是全体成员共享记忆，委派子会话反而看不到——见「频道」篇）。

## 跨会话通讯：异步投递

会话 A 的 agent 可以调用 `send_message_to_session` 向会话 B 的 agent 投一条消息：

- **异步不阻塞**：投递立即返回，B 空闲时（或按收件政策）消费一整轮。
- **地址**：agent 用 `list_conversations` 工具自己查会话地址（标题或 id），不需要你报。
- **回复**：投递时如果开了「期待回复」，B 答完会自动把结论投回 A，一次即止。
- **边界**：只投**同一项目**内的会话（跨项目会被拦并提示）；只投普通会话，不投委派子会话。

## 收件三态（每个会话各自设置）

被投递会话的**收件政策**决定来件去向，在会话头收件箱里切换：

| 政策 | 行为 |
|---|---|
| 自动接收（默认） | 来件排队，会话空闲后自动消费一整轮 |
| 需批准 | 来件扣住，你在收件箱里批准后才消费（对方的回信除外） |
| 拒收 | 投递方立即收到失败结果 |

「期待回复」的回投在需批准政策下也放行（对话要闭环）；但显式拒收永远拦。通知：失焦时收到来件会发系统通知，文案按政策区分（待批准 / 已收到）。

护栏（防刷屏）：单会话待处理队列上限 10 条；自动消费 10 分钟窗口内至多 6 次，超出留队等你手动放行。

## 怎么选

- 要**结果**回当前任务 → 委派。
- 要**告知/征询**另一个会话（不阻塞当前） → 跨会话投递。
- 要**多人讨论**同一话题 → 频道。
