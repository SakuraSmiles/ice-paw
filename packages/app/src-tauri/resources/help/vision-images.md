# 图片与视觉能力（上传 · 代读 · 配置）

## 能发图片吗

能。把图片拖进输入区或点附件按钮上传。限制：单张 5 MB 内、单条消息最多 20 张、png / jpg / jpeg / gif / webp 格式。

发出去的图怎么被「看」，取决于 agent 的模型：

- **模型本身支持视觉**（多模态）→ 图片直接给模型看。
- **模型不支持视觉** → 走**视觉代读**：由你配置的视觉模型把图片内容读成文字，交给当前 agent。气泡里会标注代读来源（如「图片经视觉模型代读为文本」），谁读了图对你是诚实的。
- 没配视觉代读、模型又看不了 → 图片被剥离并明确提示，不会静默丢弃也不会报错卡死。

## 视觉读取配置（代读链）

设置 → 通用 → **视觉读取**：配置一条「主模型 + 可选降级」的链，供所有非视觉 agent 共用。

- 每条配置独立选厂商 / 模型 / Key（Key 存在模型配置实体里的话直接引用，一处换全局生效）。
- 每条旁边有**测试**按钮：发一张最小探针图走完整链路，测过即正式可用。
- 什么时候需要它：你的主力 agent 是纯文本模型（更便宜或更快），但偶尔要处理截图/照片时不用换模型。

## 哪些图会走这套适配

不只是你上传的图：

- 消息里上传的图片（含历史消息回放）；
- 工具返回的图片（如查看附件图片、屏幕截图）。

原则是统一的：**从不向不支持视觉的模型塞图片**（那只会报错或「看不到」），该代读的代读、读不了的诚实说明。

## 常见问题

- **agent 说看不到图？** 两种情况：模型无视觉且未配视觉读取（去设置 → 通用配一条）；或代读链全挂了（错误提示里会带原因，检查视觉配置的健康状态）。
- **代读和直读差在哪？** 代读是文字转述（位置、颜色等细节有损）；要精细看图（UI 截图找按钮、图表读数）优先用视觉模型直读。
- **截图任务**：配合屏幕共享（见「屏幕读写与共享」）让 agent 自己截屏查看，比人肉截图上传更顺。
